# 人工接管协议

采集机器人运行到需要经办人人工确认的页面时，必须暂停而不是代答。本文档描述暂停、接管、核对与续采的约定。

## 原则

- 确认动作只能由人完成。系统不识别验证码、不代填确认内容、不自动点击确认。
- 人工处理期间机器人不点击、不导航；操作台只转发人工产生的输入，且转发内容不写入台账。
- 恢复采集前重新核对账号、机构、所在页面（页面标记与地址）和待采对象，不只看 URL。
- 浏览器会话丢失（进程重启、页面关闭、连接断开）时明确要求重新开始会话，不伪造续采。

## 流程与状态

1. `POST /sessions` 启动采集。遇到确认页时返回 `status=paused` 与 `takeover.claimPath`（一次性接管入口，含凭据原文，只返回给调用方，不写日志）。
2. 经办人在期限内打开接管入口领取工单（`pending → claimed`）。凭据只能领取一次，重复领取返回 409。
3. 领取后进入操作台页面（`/takeovers/:id/operate`），通过受限视图查看页面并手动操作：
   - `GET /takeovers/:id/view` 页面视图快照；
   - `POST /takeovers/:id/input` 转发人工输入（点击坐标/元素、文本、按键），台账只记录动作类型与长度；
   - `POST /takeovers/:id/complete` 声明完成，触发恢复核对；
   - `POST /takeovers/:id/abort` 放弃接管。
4. 恢复核对（`claimed → verifying`）：依次检查浏览器连接、页面存活、账号、机构、页面标记、页面地址、确认区是否消失、待采对象是否出现。任一不符则工单 `failed` 并记录原因，会话安全结束。
5. 核对通过：工单 `completed`，机器人从停止点继续采集余下资料并写入接收回执。
6. 期限到达未完成：工单 `expired`，会话关闭。进程重启时所有未结工单标记 `browser-lost`，再次提交一律拒绝并提示重新开始会话。

## 工单状态

`pending → claimed → verifying → completed`，失败分支为 `failed / expired / aborted / browser-lost`，均为终态，终态后再次提交返回 409 并附原因。

## 互斥

- 每个浏览器会话由创建它的采集工作者持有 `worker` 令牌，管理操作（如 `POST /sessions/:id/cancel`）须出示令牌，否则 403。
- 接管凭据一次领取；操作台后续调用须出示领取时签发的操作凭据，否则 403。

## 台账

`GET /ledger?session=<id>` 查看。每条事件含 `actor`（robot/human/system）与 `action`。台账只写对象标识（key/version）与动作，不写页面人员资料、确认说明文本或凭据原文。
